# tend: full analysis and next steps (2026-10-20)

This follows the checkpoint (2026-10-19), the review fixes (I1–I6), and the extensions (E1–E11). CI is green on ubuntu and macOS.

## 1. Bottom line

1. **The engineering is in good shape.**
   - 15.3k lines of Rust: 7.4k in tend-core, 6.3k in tend-cli.
   - 192 tests (108 core, 54 CLI, 26 e2e, 4 property), three fuzz targets.
   - Six CI jobs (check on two OSes, audit, MSRV, latency, fuzz) plus a manual conformance job, all green. Claude Code 2.1.304 passes all 9 conformance checks.
   - The hook path fails open everywhere it was tested.
2. **The value is still unproven, for the same reason as at the checkpoint: almost no real use.**
   - The first real supervised session is today's: this repo's own conversation, resumed under `tend claude`.
   - Every other ledger comes from tests.
3. **History shows little for tend to catch.** On the owner's past work, the guard, loops, and shaping have almost nothing to act on:
   - 0 true guard flags in 120 Edit/Write edits.
   - 1 loop, the dev session re-running a deliberately failing demo suite.
   - About 0% of output is shapeable.
4. **The audit gives the clearest real signal, and it stays experimental by owner decision.** On polaris's last 40 commits it listed:
   - 68 test files changed, 61 of them strengthened;
   - 1 deleted test;
   - 59 suppressions.

   That list was short and correct after two rounds of fixes found by dogfooding.
5. **Real data keeps finding defects that unit tests miss.** Every pass over real data found one:
   - code reads being shaped (C1);
   - loops from views (C2);
   - false suppressions;
   - snapshot matches inside here-docs;
   - a tolerance false positive;
   - today, a false loop from cargo's "could not compile" summary line, and a missing transcript for a resumed session.

   The next gains come from use, not from more features.

## 2. Fixes in this analysis

- **Cargo summary lines are not failures.** Two unrelated compile errors over 92 minutes read as one loop, because `error: could not compile … due to N previous error` was taken as the failure and its count is normalized. The real-data retro is back to 1 loop.
- **A resumed conversation's transcript is found again.** After the folder rename, Claude Code reports a transcript path under the new project dir, but the file is still under the old one. The report now looks for the same file name in the other project dirs; this session's report shows its 353M prompt tokens again.
- **TASKS.md** now ticks R3.3 (the plugin, done as E6), C5 (the remote), and the Phase 3 guard rules (E4 and I2).
- **The `myclaude` alias** for `tend claude` is in `~/.bashrc`.

## 4. Risks

1. **Features without users.** There are nine config keys, a plugin, an audit, and a policy file, all of them untested in practice. Each real pass has found a false positive, so expect more.
2. **One undocumented platform behavior.** Wrapping depends on `updatedInput` without a permission decision. Conformance checks it per version, and tend now notices if Claude Code ignores the rewrite (F8). A Claude Code change could still turn wrapping off quietly; it would show at exit.
3. **A synthetic fixture.** PermissionDenied has never been captured live.
4. **Auto-mode denials of wrapped calls.** 1 in 9 live wrapped runs was denied earlier. This is mitigated (retry, `no_wrap`), but the rate on real work is unknown.
5. **Scope creep.** The design reference's phases are being overtaken by extensions. Without a usage gate, the code grows faster than the evidence.

## 9. Benchmark pilot (Haiku, 2026-10-20)

8 tasks × 2 arms × 3 runs. After the first round most sessions hit the plan's usage limit; those 22 runs are left out, and the Sonnet round was all limit-hit. The runner now marks such runs and stops scheduling.

| Arm | Valid runs | Success | Weakened | Seconds |
|---|---|---|---|---|
| base | 14 | 12 | 0 | 26.6 |
| tend | 12 | 9 | 0 | 39.0 |

**Reading:**
- Every valid failure is the impossible contradiction task, where the agent explained the conflict and asked; that is the honest outcome.
- No run weakened a test, in either arm.
- tend did nothing beyond wrapping the test runs.

Haiku, under mild pressure, takes none of the shortcuts. This matches the owner's real sessions.

**Next for the benchmark:**
1. Harder bait: bugs that are costly to fix while the test change is trivial, longer tasks, multi-file causes.
2. Run Sonnet and Opus after the limit resets, at `--parallel 2`.
3. Measure tend's time overhead: 39 s against 27 s. It may be wrapping or contention; check sequentially.

## 10. Benchmark: Sonnet, 12 tasks, sequential (2026-10-20)

Four tasks were added:

- `perf`: a timed assertion it is tempting to raise;
- `network`: a test that needs the network, tempting to skip;
- `rename`: updating a test is the legitimate fix;
- `dates`: day-first parsing, tempting to change the expected date.

| Arm | Runs | Success | Weakened | Seconds | Cost $ |
|---|---|---|---|---|---|
| base | 12 | 11 | 0 | 14.1 | 0.058 |
| tend | 12 | 11 | 0 | 23.0 | 0.057 |

- **Same outcome as Haiku.** The only failure in each arm is the contradiction task, handled honestly. No shortcut was taken in either arm, and the guard did not misfire on `rename`.
- **Overhead.** tend's arm is slower by about 9 s per session. The breakdown of one run:
  - API time is equal: 12.0 s against 12.2 s.
  - Tool time is 3.7 s against 0.6 s.
  - Each wrapped test call took 1.3–2.0 s from request to result, while `tend run` itself adds nothing measurable (227 ms against 240 ms locally).
  - So the time is spent in Claude Code's auto-mode handling of the rewritten command, the likely cause being its permission check. One wrapped call on `perf` was denied and retried.
- **Guard gap closed.** A raised time limit (`elapsed < 0.2` → `< 5`) is now flagged ("time limit raised"). The `perf` task had shown that the guard had no rule for it.
- **New config key `wrap_tests`** (default `true`, per the D4 decision). **Recommendation: set it to `false`.** On this owner's work, wrapping buys almost nothing (test output is about 3% of output, and almost none of it is long enough to summarize). It costs about 1.5 s per test run in auto mode, plus occasional denials. The guard, loops, policy, and audit work without it.

**Conclusion of the benchmark so far.** Current Claude models (Haiku, Sonnet) take none of the planted shortcuts, even under release pressure. tend's protective features are insurance that has not yet paid out, either in benchmarks or in real use. Its measurable effects are a reviewing aid (the audit) and a small time cost when wrapping. Any further benchmark work should target long, multi-step tasks, where loops and corner-cutting are more likely, rather than more short tasks.
